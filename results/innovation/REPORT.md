## 7. Notes on method

* **Guard formula corrected after the first tuning round.** The first version took the time left of an overrunning burst as c × (CPU time used). With c < 1 that can make the burst look shorter than its own estimate, the opposite of the intended behaviour. The guard now uses max(estimate, c × CPU time used) and was re-tuned. The first round is kept in `tuning_round1.csv`; only the corrected version was run on evaluation seeds.
* **W7 was part of the tuning set.** The guard and persistent-ageing parameters were chosen on seeds 100–102 of W1–W7, so the guard was not tuned blind to the attack type. The evaluation seeds 0–9 were never used for tuning.
* **c = 0.25 is the smallest non-zero value tested.** With the corrected formula c = 0 is exactly the original Adaptive-ML, whose tuning score (0.937) is worse than c = 0.25 (0.899). Values between 0 and 0.25 were not tested.
* **Bait processes dominate W7's CPU demand.** They are 30% of the processes but 76% of the total CPU demand on average (72%–80% across seeds 0–9).
* **Noisy oracle.** Its errors are random around the true value, whereas a real predictor's errors are systematic, so the measured σ of a real predictor is only an approximate position on the σ axis. The 'equivalent σ' column gives the σ at which the noisy-oracle curve reaches the real predictor's waiting time.
* **Figure 1 shading** is the 95% interval for the 10-seed mean (mean ± 1.96 sd / √10). It shows variation between workload instances; the paired tests in section 6 are the basis for every comparison.
